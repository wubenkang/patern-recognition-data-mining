# 《Hadoop 权威指南》第四版阅读建议

## 总体建议

这本书不建议从第一页一路硬啃到最后。更高效的方式是先建立 Hadoop 的整体框架，再抓住 HDFS、YARN、MapReduce 三个核心，最后根据学习目标选择 Hive、Spark、HBase、ZooKeeper 等生态组件。

推荐主线：

```text
第 1 章 -> 第 3 章 -> 第 4 章 -> 第 2 章 -> 第 17 章 -> 第 19 章 -> 第 20 章 -> 第 21 章
```

一句话概括：先读 HDFS 和 YARN，再读 MapReduce，最后读 Hive、Spark、HBase、ZooKeeper 生态。

## 建议先读的章节

### 1. 第 1 章：初识 Hadoop

先读这一章，用来建立整体图景。

重点关注：

- Hadoop 解决什么问题
- 大数据为什么需要分布式存储和分布式计算
- Hadoop 生态由哪些组件组成
- HDFS、YARN、MapReduce 分别承担什么角色

这一章不需要背概念，读懂 Hadoop 的整体定位即可。

### 2. 第 3 章：HDFS

这是全书最重要的章节之一，建议认真读。

重点关注：

- HDFS 的设计目标
- 块、文件、副本机制
- NameNode 和 DataNode 的职责
- 数据可靠性和容错机制
- HDFS 适合什么场景，不适合什么场景

理解 HDFS 后，后面的 Hive、Spark、HBase 等内容才容易串起来。

### 3. 第 4 章：YARN

YARN 是 Hadoop 的资源调度层，也很关键。

重点关注：

- ResourceManager
- NodeManager
- ApplicationMaster
- Container
- 一个任务从提交到运行的大致流程

读这一章的目标不是掌握所有调度细节，而是理解集群资源是如何被统一管理和分配的。

### 4. 第 2 章：MapReduce

MapReduce 是 Hadoop 早期最核心的计算模型。

重点关注：

- Map 和 Reduce 的基本思想
- Shuffle 过程
- Combiner 的作用
- 输入、输出、分区、排序的大致关系

如果不是专门研究 Hadoop 底层计算，不需要一开始深挖所有 API。

## 按学习目标选择路线

### 如果目标是快速入门大数据

```text
第 1 章 -> 第 3 章 -> 第 4 章 -> 第 2 章 -> 第 17 章 -> 第 19 章
```

读完这条线，基本可以建立对 Hadoop 生态的主干认知。

### 如果目标是理解 Hadoop 底层原理

```text
第 1 章 -> 第 3 章 -> 第 4 章 -> 第 2 章 -> 第 5 章 -> 第 6 章 -> 第 7 章 -> 第 8 章 -> 第 9 章
```

这条线更偏底层，适合想理解 HDFS、YARN、MapReduce 执行机制的人。

### 如果目标是找工作或做数据开发

```text
第 1 章 -> 第 3 章 -> 第 4 章 -> 第 17 章 -> 第 19 章 -> 第 13 章 -> 第 20 章 -> 第 21 章
```

建议把 Hive、Spark、Parquet、HBase、ZooKeeper 和 HDFS/YARN 串起来看。

### 如果目标是搭建和维护集群

```text
第 1 章 -> 第 3 章 -> 第 4 章 -> 第 10 章 -> 第 11 章
```

这条线更偏运维和平台工程。

## 阅读时的抓手

读这本书时，建议始终带着几个问题：

- 数据存在什么地方？
- 任务由谁调度？
- 计算在哪里执行？
- 数据如何分片？
- 失败后如何恢复？
- 哪些组件负责离线分析，哪些组件负责实时或近实时访问？

只要能围绕这些问题建立答案，Hadoop 生态就不会显得散。

## 不建议一开始深挖的内容

以下内容可以先跳过或略读：

- MapReduce 的大量 Java API 细节
- 过时或使用较少的组件，例如 Pig、Crunch
- 集群运维的细枝末节
- 所有文件格式的底层实现细节

先建立主干，再补细节，效率会高很多。
